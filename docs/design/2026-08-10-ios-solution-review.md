# iOS WhatsApp 广播方案与代码链路评审

> 日期：2026-08-10
> 对象：`docs/design/2026-08-06-ios-whatsapp-broadcast-vpn.md` + 当前分支 `feat/ios-whatsapp-broadcast-vpn` 全部实现
> 方法：按**商业闭环**（交付→配置→激活→价值→运营→增长）与**用户体验**（添加→注册→反馈→使用→恢复）两条链路逐段核对，标注闭环/断点。

## 1. 完整链路现状盘点

```text
① 平台添加设备 ──► 生成注册码二维码
② App 扫码/手动输入 ──► 注册（installationId 唯一，一行）
③ 服务器下发配置 ──► 虚拟 IP(顺序) / 服务器地址 / secret
④ App 上报 online ──► 平台状态在线
⑤ 组网（easytier）──► 服务端 peer 可见 / 平台"组网=True"
⑥ 双向 ping 通 ──► 链路可达
⑦ 使用（WhatsApp 群发）──► ❌ 未实现（M2 之后）
⑧ 持续运营（心跳/恢复/禁用/日志）──► ⚠️ 部分实现
```

| 环节 | 状态 | 说明 |
|---|---|---|
| ① 添加设备 | ✅ 闭环 | 前端「添加设备」→ 二维码 + 可复制注册码 |
| ② 注册 | ✅ 闭环 | App 扫码/手动输入；installationId 持久化，同一手机始终一行；IP 顺序递增 |
| ③ 配置下发 | ✅ 闭环 | relayHost/relayPort/虚拟 IP/secret 下发 |
| ④ 在线判定 | ⚠️ **断点** | App 只在注册/恢复时上报一次 status；**无周期心跳** → App 运行 90s 后平台误判 offline |
| ⑤ 组网 | ⚠️ **半闭环** | Mac/HK 模拟 easytier 验证了服务端链路；**App 内嵌 startTunnel 仍是 stub**（M3），真机 App 无法真正组网 |
| ⑥ 双向 ping | ✅ 链路验证（模拟设备） | 真机未验证 |
| ⑦ 群发核心业务 | ❌ 未实现 | WDA 驱动、任务/租约/幂等、前端群发——商业价值未闭环 |
| ⑧ 持续运营 | ⚠️ 部分 | 事件日志✅；设备禁用/删除/恢复❌；RPC 公网暴露⚠️；容量监控❌ |

## 2. 商业闭环缺口（按阶段）

### 2.1 交付（设备如何进入平台）
- ✅ 添加设备 = 生成注册码二维码，扫码即注册——**用户获客/交付体验已闭环**。
- ⚠️ **缺租户设备配额**：方案容量按 5000 设备设计，但平台无"租户设备上限/剩余名额"展示与控制；无配额，成本不可控（每设备 = 常驻 easytier peer + 服务器资源）。
- ⚠️ **缺设备命名/标识补充**：注册后设备默认名"移动设备"，用户在平台可改名（PATCH 有），但无默认规范（如按型号+时间）。

### 2.2 激活（用户能否真正用起来）
- ⚠️ **App 组网未完成（最大商业断点）**：当前 startTunnel 是 stub（`notImplementedYet`），真机 App 无法真正连上 HK easytier。用户拿到 App 后**无法完成"注册→组网→可用"的闭环**，体验停在注册成功。
- ⚠️ **组网状态不实时**：前端 `networkingConnected` 是列表请求时点查询（调 easytier-cli），无轮询/推送；用户/管理员看不到实时变化。

### 2.3 价值（核心业务是否交付价值）
- ❌ **WhatsApp 群发（WDA 自动化）完全未实现**：无任务创建、租约、幂等、发送状态机、unknown 处理。商业价值（自动群发）未闭环——这是**产品存在的根本理由**，目前只有"设备注册+组网"的壳。

### 2.4 运营（设备如何持续可用）
- ⚠️ **App 心跳断点**：无周期 `/status` 上报 → 平台 90s 后误判离线；真实可用性无法反映。
- ⚠️ **缺设备禁用/删除/恢复**：平台只能改名；设备丢失/故障/退役无法处置（设计 11.3 的 probe/recover/retire 未实现）。
- ❌ **缺恢复 SOP 自动化**：设备 recovery_required → 人工 USB 恢复（有文档）→ 平台"恢复"动作未实现。
- ❌ **缺容量/健康监控**：easytier peer 数、进程、RPC、5000 设备容量阈值无监控/告警（方案 5.6.5 未落地）。
- ⚠️ **RPC 安全**：HK easytier RPC（15888）实测监听 0.0.0.0（配置是 127.0.0.1），公网可达且无鉴权——**必须封禁**（安全组/防火墙），否则任何公网用户可控制 easytier。

### 2.5 增长（复用与扩展）
- ✅ 数据库 mobile_devices 带 platform 字段，兼容未来 Android。
- ⚠️ 注册码是"租户级复用"，无"每设备一次性码"或"码的批次/失效管理"；大批量交付（5000）缺少批量注册/导入能力。

## 3. 用户体验断点（按用户旅程）

| 步骤 | 现状 | 问题 |
|---|---|---|
| 平台添加设备 | 二维码+可复制 | ✅ 顺手 |
| App 打开注册页 | 平台地址+注册码+扫码 | ✅ |
| 扫码 | AVFoundation 实现 | ⚠️ 模拟器不可用，真机待验；无扫码失败/权限被拒引导 |
| 注册成功 | 进设备状态页（设备ID/虚拟IP/服务器ID） | ⚠️ **无成功动效/明确"注册成功，组网中"状态**；VPN profile 保存失败只在小字提示（模拟器），真机用户可能困惑 |
| 组网状态 | App 状态页无"组网中/已组网/失败"展示 | ❌ 用户不知道设备是否真正连上服务器 |
| 重新注册/换租户 | 无"退出/重新注册"入口 | ❌ 注册错租户/换手机无法自助重来 |
| 设备下线/故障 | 平台显示 offline/组网False | ⚠️ 无恢复引导（App 无"重新连接"操作，平台无恢复按钮） |
| 错误反馈 | 表单错误/注册失败有提示 | ⚠️ 扫码失败、网络错误、VPN 错误未分类友好提示 |

## 4. 技术/安全/容量缺口

1. **App 周期心跳缺失**：应前台每 20s 调 `/status`（或 WSS heartbeat 由服务端更新 last_app_seen_at），否则在线判定失真。
2. **App startTunnel stub**：M3 未做；真机组网依赖 FFI 完整调用（TUN fd、collect_network_infos、peer 等待）。
3. **easytier RPC 公网暴露**：15888 需封禁（ufw/安全组），当前仅 ufw 放行了 11010/11011，15888 虽未显式放行但 easytier 绑 0.0.0.0，云安全组若全放行则暴露——需核实封禁。
4. **network_secret 泄露面**：HK 官方 easytier 二进制启动日志打印明文 secret（fork 脱敏未用于 HK 测试服务端）——需换用 fork 脱敏二进制。
5. **容量/监控**：5000 设备无监控、无压测、无容量验证（M0-A 只验证了构建/链接）。
6. **前端组网状态非实时**：无轮询/WS 推送。

## 5. 问题清单（按优先级）

### P0（商业闭环必需，阻塞价值交付）
- P0-1 实现 WhatsApp 群发核心业务（任务/租约/幂等/发送状态机/unknown）——价值不闭环，其余都是铺垫。
- P0-2 App 周期心跳（前台 20s `/status`），保证在线判定真实。
- P0-3 封禁 easytier RPC 公网（15888）+ HK 服务端换 fork 脱敏二进制。

### P1（体验与运营闭环）
- P1-1 App 真实组网（startTunnel 完整接入 FFI：TUN fd → set_tun_fd → peer 等待 → connected）——真机可用前提。
- P1-2 平台设备禁用/删除/恢复/探活（设计 11.3 补齐）。
- P1-3 组网状态实时（前端轮询或 WS）。
- P1-4 App 注册成功引导 + 组网状态展示（连接中/已连接/失败 + 重试）。

### P2（体验打磨与容量）
- P2-1 重新注册/退出/换租户入口。
- P2-2 错误分类友好提示（扫码/权限/网络/VPN）。
- P2-3 租户设备配额展示与控制。
- P2-4 5000 容量压测 + easytier/peer 监控告警。

## 6. 分阶段改进计划

- **阶段一（商业闭环地基）**：P0-2 心跳 → P0-3 安全封禁 → P1-2 设备禁用/恢复 → P1-4 成功引导。
- **阶段二（核心价值）**：P0-1 WhatsApp 群发（M2 controller + M1 任务/租约/幂等 + 前端群发页）。
- **阶段三（真机可用）**：P1-1 startTunnel 完整接入 + 真机验证（扫码→注册→组网→双向 ping）。
- **阶段四（规模与运营）**：P1-3 实时状态 → P2 系列（配额/监控/压测/错误体验）。

## 7. 结论

当前代码在「设备交付与注册」环节已形成较好闭环（二维码扫码、installationId 一行、IP 顺序、事件日志、在线/离线、组网对应），但**整条商业链路未闭环**：

1. **价值断点**：WhatsApp 群发核心业务未实现——产品没有交付价值；
2. **可用断点**：App 真实组网（startTunnel）未实现 + 无周期心跳——设备"看似注册成功却不可用/被误判离线"；
3. **运营断点**：设备禁用/恢复/配额/监控缺失；
4. **安全断点**：easytier RPC 公网暴露、HK 服务端明文 secret 日志。

建议按上述阶段推进：先补齐地基（心跳/安全/设备管理），再实现群发核心价值，再真机验证组网闭环，最后规模运营。
